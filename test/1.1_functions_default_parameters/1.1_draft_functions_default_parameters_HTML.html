1. Introduction: The Standard Protocol

In any hospital or research lab, you'll find "standard operating procedures" or SOPs. When you run a common diagnostic test like a Complete Blood Count (CBC), the hematology analyzer is already configured with default settings for a typical adult patient. The machine doesn't ask for the normal range of red blood cells every single time; it already knows the standard. However, if you're testing a pediatric patient, a clinician can override these defaults. This combination of a reliable standard and the flexibility to adapt is what makes the process efficient and powerful.

This section will guide you through using this same concept in Python. We'll explore how default parameters act as your function's built-in SOP, providing a "standard" value that is used automatically unless you provide a different one. By the end of this journey, you will be able to define functions with default parameters, explain the rationale for their use in a clinical context, call them by both using and overriding defaults, and crucially, recognize and correct common pitfalls like using mutable objects as defaults to avoid syntax errors and data contamination. This is more than a convenience; it's a cornerstone of writing clean, flexible, and reproducible code—a critical principle of modern computational biology.

2. Key Concepts and Definitions

Before we dive into the examples, let's establish our terminology, much like defining terms before a clinical trial.

Key Terms
Function: A named, reusable block of code that performs a specific, well-defined task, like a protocol to calculate a patient's medication dosage.
Parameter: A variable name listed inside the parentheses in a function's definition. It acts as a placeholder for the data the function needs, like a required field on a medical form (patient_weight).
Argument: The actual value or data that you pass into the function when you call it. If the parameter is patient_weight, the argument might be 70 (for 70 kg).
Default Parameter: A parameter that is assigned a default value directly in the function definition. If you call the function without providing an argument for that parameter, Python will automatically use this pre-defined value.

3. Main Content

In Python, you can provide default values for function parameters. This makes an argument optional when the function is called. If the caller doesn't provide a value for that argument, the default value is used instead.

4. Practice Exercises

Exercise 1: Calculating Body Mass Index (BMI)
10 minutes Basic

Objective: Create a function that uses a default parameter to handle different unit systems while incorporating robust error handling.

Medical Context: Dr. Evans, a primary care physician, needs a quick tool to calculate BMI. The formula is BMI = weight / (height * height). Her clinic uses kilograms and meters, but referrals sometimes use pounds and inches.

View Solution 
from typing import Union

# Define conversion factors as constants
LB_TO_KG = 0.453592
INCH_TO_M = 0.0254

def calculate_bmi(
    weight: Union[int, float], 
    height: Union[int, float], 
    units: str = "metric"
) -> float:
    """Calculates Body Mass Index (BMI) from weight and height.

    Handles both metric and imperial units and includes error checking.

    Args:
        weight (Union[int, float]): Weight of the patient.
        height (Union[int, float]): Height of the patient.
        units (str): The unit system for weight and height. 
                     Accepts 'metric' or 'imperial'. Defaults to 'metric'.

    Returns:
        float: The calculated BMI, rounded to one decimal place.

    Raises:
        ValueError: If units are not 'metric' or 'imperial', or if height is not positive.
    """
    # Because manual unit conversions are a leading cause of 'researcher-induced' error.
    if units.lower() == "imperial":
        weight = weight * LB_TO_KG
        height = height * INCH_TO_M
    elif units.lower() != "metric":
        raise ValueError(f"Unknown units: '{units}'. Please use 'metric' or 'imperial'.")

    if height <= 0:
        raise ValueError("Height must be a positive number.")
    
    bmi = weight / (height ** 2)
    return round(bmi, 1)

# --- Test Cases ---
# Patient A: 70 kg, 1.75 m
bmi_metric = calculate_bmi(weight=70, height=1.75)
print(f"Patient A's BMI (Metric): {bmi_metric}")
# Output: Patient A's BMI (Metric): 22.9

# Patient B: 154 lbs, 69 inches
bmi_imperial = calculate_bmi(weight=154, height=69, units="imperial")
print(f"Patient B's BMI (Imperial): {bmi_imperial}")
# Output: Patient B's BMI (Imperial): 22.7

Explanation: The function first validates the units string. It then converts imperial units to metric if specified. Before calculating, it checks that height is a positive number to prevent a ZeroDivisionError. This makes the function robust against common input errors.

Key Learning: Default parameters are excellent for setting a "standard mode" of operation (metric) while providing an easy way to switch to an alternative mode (imperial). Combining them with error handling creates professional, reliable code.

Exercise 2: Check for Understanding
2 minutes Basic

Objective: Identify the correct function signature based on Python's parameter ordering rules.

Medical Context: A geneticist is writing a function to analyze gene expression data. The analysis is almost always done on human genes (species="human"), but they want the option to analyze mouse data. Which function definition is syntactically correct?

A) def analyze_expression(gene_id, species="human", threshold=0.95):

B) def analyze_expression(species="human", gene_id, threshold=0.95):

C) def analyze_expression(gene_id, threshold=0.95, species):

View Solution

Answer: A is correct.

Explanation: Python's syntax requires that all non-default (required) parameters like gene_id must be listed before any default parameters like species and threshold. Option B violates this by placing a default parameter before a required one. Option C is invalid because species is listed at the end without a default value, making it a required parameter that follows a default one.

Key Learning: Required parameters always come first in a function definition.

Exercise 3: Fixing the Mutable Default Trap
5 minutes Intermediate

Objective: Identify and correct a function that improperly uses a mutable default parameter.

Medical Context: A junior developer wrote a function to add symptoms to a patient's record. However, symptoms from one patient are leaking into the next patient's record, a critical data integrity failure. Your task is to fix the log_symptom function.

# BROKEN CODE
def log_symptom(patient_id, symptom, symptoms_list=[]):
    symptoms_list.append(symptom)
    print(f"Patient {patient_id} reports: {symptoms_list}")
    return symptoms_list

# Test calls that reveal the bug
p1 = log_symptom("PT00A451", "headache")
p2 = log_symptom("PT00B729", "fever") # This should NOT include "headache"
View Solution 
from typing import List, Optional

# CORRECTED CODE
def log_symptom_fixed(patient_id: str, symptom: str, symptoms_list: Optional[List[str]] = None) -> List[str]:
    if symptoms_list is None:
        symptoms_list = [] # Create a new list if one isn't provided
    symptoms_list.append(symptom)
    print(f"Patient {patient_id} reports: {symptoms_list}")
    return symptoms_list

# Test calls now work correctly
p1_fixed = log_symptom_fixed("PT00A451", "headache")
p2_fixed = log_symptom_fixed("PT00B729", "fever")

Explanation: The original function used an empty list [] as a default. This list is created once and shared across all calls. The corrected function uses None as the default and creates a new, empty list inside the function whenever one isn't provided, ensuring each patient record is "sterile" and separate.

Key Learning: Always use None as the default value for mutable types like lists or dictionaries, then create a new instance inside the function.

5. Practical Applications in Precision Health

These are not just abstract examples. Here are some thought experiments on how you would apply this concept in a precision health setting:

Genomic Analysis Pipelines

You could design a filter_reads function for a DNA sequencing pipeline to use a standard quality score of 20 by default, but still allow a specialist to use a more stringent score of 30 for cancer-related gene variant analysis. The function signature would be def filter_reads(reads_file, quality_score_min=20):.

A Phred quality score of 20 is a common threshold indicating 99% base call accuracy.

Drug Dosage Calculations

You could write a function calculate_metformin_dose that uses a standard initial dose of 500mg for metformin (Glucophage), but lets a clinician override it based on a patient's specific profile, such as renal function measured by estimated Glomerular Filtration Rate (eGFR). The signature might be def calculate_metformin_dose(patient_weight, egfr, start_dose_mg=500):.

This embeds the standard clinical guideline directly into the code.

Risk Score Models

You could design a calculate_cvd_risk function with default statistical coefficients from a landmark study like the Framingham Heart Study. The signature could be def calculate_cvd_risk(age, cholesterol, is_smoker, bp, risk_coefficient=0.05):.

This allows a researcher to easily apply a validated model but also provides the flexibility to tweak coefficients to test a new hypothesis.

6. Summary and Key Takeaways

In this section, we've explored how default parameters allow us to create functions that are both powerful and convenient. By assigning a default value, we establish a "standard case," simplifying the function's use for common scenarios while retaining the flexibility to handle exceptions.

Key Takeaways

  • Establish a Standard: Default parameters embed a "standard operating procedure" into your function, making code for common tasks cleaner and more readable.
  • Provide Flexibility: They allow users to override the standard values when a situation—be it a unique patient case or a novel research experiment—calls for a custom approach.
  • Order is Critical: You must always define required (non-default) parameters before any default parameters in a function signature to avoid a SyntaxError.
  • Beware Mutable Defaults: Never use a mutable object like a list ([]) or dictionary ({}) as a default value. The safe pattern is to use None as the default and
